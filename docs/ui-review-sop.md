# 界面审核 SOP

每次界面变更与发布都执行。主题可读性属于验收要求，不能等待用户报告后才检查。

## 覆盖范围

1. 浅色、深色各跑一轮；自动主题检查跟随系统深浅色变化。
2. 桌面约 1440×900、手机约 390×844；检查初始画面、滚动后的吸顶栏和固定操作条。
3. 目录卡片、各筛选菜单、旅行历程、阅读工具、选句条、复制面板、笔记、设置、选稿与打印界面。
4. 默认、悬停、选中、键盘焦点、加载中、禁用与提示反馈。检查文字、图标、勾选标记、输入框和占位文字，不能只检查主按钮。

## 检查方法

- `npm run qa:themes` 生成 `artifacts/theme-contrast-results.json` 和深浅主题桌面/手机截图。普通可用文字要求至少 4.5:1，纯图标控件至少 3:1；扫描计入透明度，并从真实渲染画面取背景像素，覆盖渐变和浮层。
- 审阅截图，确认没有文字或图标融入背景、文字裁切、弹窗遮挡、横向页面溢出。禁用状态也必须能辨认用途，并区别于可用状态。
- 用键盘聚焦关键操作，确认焦点可见；验证复制中的禁用状态与完成提示。自动主题在系统深浅切换后要重新检查。
- 对新入口扩展自动脚本；不能因为已有其他主题截图就跳过本次修改所在的页面和状态。
- 修改强调色时查找全站相同颜色用途，核对正文强调色与填充按钮。填充背景和前景必须成对定义，检查后续 CSS 是否覆盖配套颜色；不要用整行低透明度淡化可用按钮。
- 打印预览保留纸张颜色；打印输出单独回归，不应把深色界面底色带入 PDF。

`npm run publish:pages` 会在构建后自动运行主题审核；检查失败则停止部署。

## 完成条件

自动检查通过，截图已审阅，相关功能回归通过后才提交发布。发布后检查正式域名及深色关键按钮。若某项无法验证，明确记录阻碍和实际覆盖范围，不宣称全部通过。
